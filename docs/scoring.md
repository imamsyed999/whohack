# Local behavior scoring

whohack aggregates 60 seconds of observed behavior for each `(PID, creation time)`.
Executable changes reset that window. It tracks destination/port counts, raw-IP
connections, children, sensitive accesses, persistence, bytes, connection interval
variation, unexpected capability severity, taint, signature and path class.
Windows ETW emits aggregated send/receive deltas; polling explicitly reports byte
visibility as unavailable. Missing telemetry is not interpreted as evidence of safety.

Memory is bounded to 1,024 process windows, 2,048 samples per process, and 65,536
samples overall. Resource pressure sets `window_saturated`, which downstream state
and training exports retain. PID reuse, out-of-order events and expiration are tested.

The fallback is the specification's untrained heuristic: unexpected severity / 6,
plus 0.2 for taint and 0.2 for an unsigned file, clamped to [0,1]. This score is not a
calibrated probability. Rules and model fusion decide which actions are warranted.

Optional `[tier1] model` and `sha256` configuration loads a local ONNX artifact with
the exact version-1 feature order in `whohack_detect::window::FEATURE_NAMES`. It must
have a `[1,17]` float input and a single finite score output in [0,1]. The loader
checks its digest and size before parsing those same bytes. No inference request
or telemetry leaves the machine.

`ml/fixtures/toy-tier1.onnx` is an explicitly synthetic loading/inference fixture,
generated by `ml/make_toy_model.py`. It is not enabled in the preview and is not a
trained malware detector. Model quality requires the family-separated evaluation
and human review described in the training milestone.

```powershell
# Replay exports the same feature schema used by live detections:
target/debug/whohack-service.exe --replay .vigil/beacon-replay.jsonl --category pdf_reader
# Explicit config loads the same pinned Tier 1 model and custom rules as runtime:
target/debug/whohack-service.exe --replay .vigil/beacon-replay.jsonl --category pdf_reader --config .vigil/windows/config.toml
```

Replay reports `scorer` and `score`; the same score enters detection and the
`ANOMALY` state line. No explicit config means the heuristic and built-in rules.
Configured model errors stop replay so training cannot silently mix scorers.

```sh
cargo test -p whohack-detect
cargo run --release -p whohack-detect --example score_bench
```

October 2026 local development-machine measurement (WSL build host, one CPU thread,
3,000 timed events after warmup, saturated 2,048-event window): p50 25.938 microseconds,
p95 33.591 microseconds for window aggregation plus heuristic scoring. This measures
the local machine, not the minimum supported four-core PC or detector accuracy.
